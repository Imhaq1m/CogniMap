[S9] Prompts per stage (draft, model-agnostic JSON-only)
---------------------------------------------------------
All server-side: resolve text by owned ids first, never trust client text, then inject into {braces}.
- [x] P1 extract_concepts(markdown, figures): system "extract study concepts from course docs only, no external knowledge; synthesize scope-grounded text when missing, mark generated + cite pages; if partial say partial." User injects MARKDOWN + FIGURES_JSON + RULES (JSON list only, fields concept_id/title/kind:main|sub/parent_id/source:extracted/explanation_type/explanation_text/explanation_source:extracted|generated/pages/diagram_refs/diagram_description; link figures via page overlap; never user_added). Retry once on bad JSON -> stub fallback. (implemented in llm.py: P1_SYSTEM + build_p1_user, chain advances on bad JSON)
- [x] P2 evaluate_paraphrase: system "lenient tutor, meaning over wording, hints never answers." User injects REFERENCE explanation_text + TYPE + PAGES + DIAGRAM + STUDENT paraphrase -> {passed,accuracy,originality,feedback,hint}. Pass if core meaning in own words. Blue user_added: skip prompt, code bypass with plausibility-check + warning_ack. (implemented in llm.py: P2_SYSTEM + build_p2_user + validate_paraphrase_eval_shape; balanced bands, app derives passed; hint guardrail; blue bypass in code)
- [ ] P3 generate_scenario: system "verbalize only, do not invent concepts." User injects CHUNK_IDS (2-3, 1 only if n==1) + CONTEXT + MAINS_BACKGROUND display-only -> {scenario_id,text,concept_ids:chunk unchanged}. App validates ids == chunk.
- [ ] P4 evaluate_scenario: system "grade per-selection vs scenario facts + reference; tier 1 wrong-concept not-related, tier 2 right-concept wrong-justification hint, tier 3 pass." Per-selection inject SCENARIO + CONCEPT title/text/pages + JUSTIFICATION + BLUE flag (user text as ground, prefix "user-defined — plausibility check, not doc-cited"). Return {concept_id,passed,feedback,hint}. App computes missed_ids + cleared (missed empty AND all passed).
- [ ] P5 probe_link: system "probing analyst, grade Why/Fail independently, side-targeted hints." Inject EDGE A -type-> B + A_REF + B_REF + BLUE flag + WHY_ANSWER + FAIL_ANSWER -> {why_passed,why_feedback,why_hint,fail_passed,fail_feedback,fail_hint}. Same prompts for custom edges. App brightens only when both true.
- [x] Provider syntax (Gemini): google-genai SDK, response_mime_type="application/json", low temperature (0.2-0.3) for extract/eval determinism, system_instruction carries the system lines above. Same prompt text for 3.8/3.7/3.6 — no per-model prompt fork. No function-calling dependency.
- [x] Provider syntax (GLM, default since S2b): raw httpx POST https://api.z.ai/api/paas/v4/chat/completions, Bearer GLM_API_KEY, temperature 0.2, response_format {"type":"json_object"}, max_tokens cap. GLM-4.7 thinking is compulsory: reasoning may arrive in reasoning_content next to the JSON answer in content (parser reads content only). Same prompt text for both providers — no per-provider prompt fork. Gemini syntax line above stays valid when LLM_PROVIDER=gemini (archived).
- [x] Caching (locked): implicit-only, stable-prefix-first. All three chain models support implicit (default on, min 4096 tokens, savings auto via usage.total_cached_tokens) + explicit, but explicit deferred (extra lifecycle; caches don't share across 3.8/3.7/3.6 fallback). Keep stable content first + variable answers last in P1-P5 to maximise hit chance; extract (full markdown) is the only call likely to hit.
